# Issue #755: ISBN identity proof replay

The operator explicitly approved the #658 product rule for this implementation: a fetched page stating the candidate's normalized plausible ISBN names the same book regardless of title/author wording; a different plausible ISBN for the same title is a conflict; candidates without an ISBN keep their existing behavior. The 2026-10-27 issue comment also authorizes ISBN extraction from fetched product URLs.

## Inputs and method

- Historical stage: `git show 8bf8f09:runs/current-weekly-pilot-russian/grounded-description-stage.json` (2026-10-26).
- Candidate ISBNs, titles, and authors: `runs/current-weekly-pilot-russian/latest-scouting-candidates.json` at baseline `d5d9191`.
- Select every `attempted_no_description` outcome with a current candidate ISBN. Re-fetch every retained rejected URL except `source_outside_policy` through the production `BoundedHTTPFetcher`, with its default response, timeout, redirect, challenge-retry, and host-rate limits. Classify URLs with the committed owner policy. Four workers perform independent fetches.
- Baseline comparison: parse the exact same HTTP response bytes and final URL through `origin/main`'s unmodified fetcher and gate (baseline `d5d9191`); no second network fetch for this comparison. Structured page ISBNs take precedence over URL extraction. “Page text” means the existing visible-text ISBN matcher found the candidate's ISBN even though no structured ISBN was extracted.
- Check each source's identity reason and identity evidence, and run the complete grounding gate on each book's successfully re-fetched rejected pages. `no_author_evidence` means title checks alone passed, but the page provides neither ISBN proof nor target-author evidence.
- No discovery, synthesis, model call, or weekly-state update. No file under `runs/` was modified. Previously accepted pages are absent from this artifact, so these are eligibility measurements for the retained rejected URLs, not a rerun of the entire historical stage.
